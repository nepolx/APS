# СМО — Техническая поддержка облачного сервиса (Yandex Cloud)

Имитационная модель системы массового обслуживания (СМО) в курсовой работе «Создание имитационной модели вычислительной системы».

## Вариант 18

| ИБ | ИЗ2 | ПЗ1 | Д1ОЗ1 | Д1ОО1 | Д2П2 | Д2Б4 | ОР1 | ОД3 |
|----|-----|-----|-------|-------|------|------|-----|-----|

### Расшифровка кода варианта

| Код | Расшифровка |
|---|---|
| **ИБ** | Источник бесконечного типа — генерирует заявки бесконечно, число источников не ограничено |
| **ИЗ2** | Закон генерации заявок — **равномерный** |
| **ПЗ1** | Закон обслуживания на приборе — **экспоненциальный** |
| **Д1ОЗ1** | Дисциплина постановки в буфер — **«по кольцу»**: поиск свободного места ведётся циклически от указателя |
| **Д1ОО1** | Дисциплина отказа — **«отказ под указателем»**: если указатель обошёл весь буфер и не нашёл места, вытесняется заявка, стоящая на позиции указателя |
| **Д2П2** | Выбор прибора — **«по кольцу»**: свободный прибор ищется циклически от указателя |
| **Д2Б4** | Выбор заявки из буфера — **приоритет по номеру источника, по одной заявке** (не пакетом) |
| **ОР1** | Автоматический режим — **сводная таблица результатов** |
| **ОД3** | Пошаговый режим — согласно варианту предполагает временные диаграммы; в данной реализации заменено табличным календарём событий (п.5 памятки — временные диаграммы визуализировать не требуется) |

## Бизнес-домен

**Техническая поддержка облачного сервиса (Yandex Cloud).**

Клиенты платформы подключены к одному из тарифных планов технической поддержки — **Basic**, **Business** или **Premium** — и направляют обращения (тикеты) в единую очередь поддержки. Из-за ограниченного числа операторов не все обращения могут быть обработаны сразу, поэтому система распределяет тикеты по приоритету тарифа и в пиковые моменты нагрузки вытесняет из очереди наименее приоритетные обращения.

### Маппинг домена на элементы СМО

| Элемент СМО | Сущность бизнес-домена | Назначение |
|---|---|---|
| Источник (ИБ, ИЗ2) | Клиенты тарифов Basic / Business / Premium | Генерируют обращения в поддержку; поток каждого источника бесконечен, интервалы между обращениями распределены равномерно |
| Заявка | Тикет технической поддержки | Содержит id источника, тариф (приоритет), время создания, статус |
| Буфер | Очередь тикетов (Тикет-система) | Кольцевой массив фиксированного размера; каждый слот хранит один ожидающий тикет |
| Диспетчер постановки (Д1ОЗ1, Д1ОО1) | **Роутер тикетов** (`TicketRouter`) | Принимает новый тикет и решает, поставить ли его в очередь (кольцевой поиск от указателя) или выполнить отказ/вытеснение при переполнении. Работает только с буфером, ничего не знает об операторах |
| Прибор (ПЗ1) | Оператор технической поддержки (`SupportAgent`) | Обрабатывает один тикет за раз; время обработки — экспоненциально распределённая случайная величина |
| Диспетчер выбора (Д2П2, Д2Б4) | **Модуль назначения** (`AssignmentDispatcher`) | При освобождении оператора выбирает из очереди один тикет с наивысшим приоритетом тарифа и назначает его свободному оператору, найденному циклическим перебором |
| ОР1 | Сводная таблица результатов | Количество заявок, отказов, время ожидания/обслуживания, загрузка операторов |

Приоритет тарифов при выборе из буфера: **Premium > Business > Basic**.
